# Rollar — 2026-11-21

Egasi: «loyihani qulaylashtirib chiqish kerak, rollar bilan ishlashni ham qo'shish kerak».

## Hozirgi holat (tadqiqot)

- Kirish huquqi faqat bo'limdan bilvosita kelib chiqadi: `staff.MODULE_DEPTS` (modul → bo'limlar). Hammasi bitta
  joyda hisoblanadi: `User.modules()` / `can_module()` (har app views'ida `check`).
- CRM rahbari — yashirin qoida (`crm/access.is_sales_head`): ega/admin, Rahbariyat yoki Sotuv bo'limida xodimlari
  bor odam. Xodimga «rahbar» huquqini to'g'ridan-to'g'ri berib bo'lmaydi.
- Boshliqlik huquqlari (`User.heads[].perms`) — UI bor, lekin huquq ro'yxati bo'sh (`perm_names: {}`).
- Jarvis'da `erp.user_role` + `erp.role_perm` (rol → amal) bo'lgan: seller, sales_head, accounting, warehouse,
  workshop, purchase, marketplace, management.

## Reja

1. `staff.AccessRole` (kalit, nom, izoh, ruxsatlar ro'yxati, tizim roli) va `User.access_roles` (M2M).
   Ruxsatlar katalogi `PERMS`: har modul (`crm`, `sales`, `money`, …) + `crm.head` (sotuv rahbari).
2. `User.perms()` = rollar ruxsatlari; `modules()` = bo'limdan + roldan (eski qoida buzilmaydi);
   `User.can(perm)` — ega/admin/Rahbariyat — hammasi.
3. Boshlang'ich rollar (migratsiya, Jarvis'dan): Sotuvchi, Sotuv rahbari, Buxgalter, Omborchi, Sex ustasi,
   Logist, Marketplace operatori, Kadrlar, Rahbariyat.
4. CRM: `is_sales_head` — `crm.head` ruxsati ham.
5. API: `/app/api/roles` (ro'yxat + katalog; yaratish), `/app/api/roles/<id>` (tahrir), `/delete`;
   `/app/api/users` — `roles`; tahrirda `roles: [kalit]`; `/me` — `perms`, `roles`.
6. Frontend (Xodimlar): xodim muharririda «Rollar» (belgilash, har rol nimaga ruxsat berishi ko'rinadi);
   «Rollar» oynasi — ro'yxat, yaratish, ruxsatlarni belgilash, o'chirish (tizim rollari o'chirilmaydi).
